# Bumao Core 开源发布教程（新手版）

**适用对象**：不会用 GitHub 的完全新手  
**前提条件**：一台能上网的电脑 + 一个浏览器

---

## 第一步：准备环境（5 分钟）

### 1. 注册 GitHub 账号

1. 打开 https://github.com
2. 点右上角「Sign up」
3. 填邮箱、密码、用户名 → 完成验证
4. 进入首页后随便创建一个空仓库测试一下

### 2. 安装 Git（如果没装过）

下载：https://git-scm.com/download/win  
安装时全部默认下一步即可。

安装完成后右键任意文件夹 → 应该能看到「Git Bash Here」菜单项。

---

## 第二步：创建你的仓库（3 分钟）

1. 登录 GitHub → 点击右上角 **+** → 「New repository」
2. **Repository name** 填你想要的名字，比如 `my-bumao-community`
3. **Description** 写一句话介绍你的项目
4. **Public**（公开）或 **Private**（私有）按需选——**建议先 Public 做测试**
5. ❌ 不要勾选 "Initialize this repository with a README"（我们已经有自己的 README）
6. ✅ 不要勾选 "Add .gitignore"（我们会自定义排除规则）
7. ✅ 不要勾选 "Choose a license"（我们自己选）
8. 点「Create repository」

成功后你会看到一个类似这样的页面，记住顶部的 URL：
```
https://github.com/你的用户名/my-bumao-community.git
```

---

## 第三步：上传文件（8 分钟）

### 方法 A：手动打包上传（最简单，推荐新手）

1. 把发行版要发布的目录压缩成一个 zip 文件：
   ```
   community/  →  选中所有文件  →  右键「发送到」→「压缩(zipped)文件夹」
   ```

2. 进入你的 GitHub 仓库页面

3. 找到绿色的「Add file」按钮 → 选择「Upload files」

4. 把你的 zip 文件拖进去

5. 底部填上提交消息，比如 "Initial release: Bumao XTGL Community v1.0"

6. 点「Commit changes」✅

**完成！** 现在你的文件就在 GitHub 上了。

### 方法 B：命令行方式（进阶，适合以后长期维护）

```bash
# 1. 进入发行版目录
cd <工程根>\community

# 2. 初始化 git
git init

# 3. 关联远程仓库（替换成你自己的 URL）
git remote add origin https://github.com/你的用户名/my-bumao-community.git

# 4. 添加所有文件
git add -A

# 5. 提交
git commit -m "Initial release: Bumao XTGL Community v1.0"

# 6. 推送到 GitHub
git branch -M main
git push -u origin main
```

## 第四步：清理与整理

### 需要删除的内容（正式公开发布前）

| 内容 | 处理方式 | 理由 |
|------|----------|------|
| `web_config.local.json` | **不上传** | 包含本机真实路径 |
| `__pycache__/` | 不上传 | Python 自动生成的缓存 |
| `*.bak*` / `*.tmp` | 不上传 | 备份临时文件 |
| `core_manifest.json` | 不上传 | 内部治理文件 |
| `.git/` 和 `.gitignore` | 不上传 | Git 自身管理 |

**最简单的方法**：只上传上面列出的"必须包含"部分，新建一个干净的 zip。

## 📚 常见问题

### Q：我改了代码还能更新吗？
A：当然！改完跑 `engine.py check --strict` 通过后，重新打包上传新版本。在 Releases 里打 v1.1、v2.0 等标签。

### Q：别人 fork 了我的仓库怎么办？
A：fork 是完全正常的，别人可以基于你的代码开发自己的分支。你不允许的话可以在仓库设置里关闭 PR 功能。

### Q：我能闭源卖钱吗？
A：可以。本仓采用 Apache-2.0，属宽松许可，允许商用与闭源再分发；义务是保留 LICENSE／NOTICE 并标注改动。强制开源的 GPL 类许可不适用于本仓。

### Q：我用了这个出了安全问题谁负责？
A：**软件按原样提供，无担保**。使用者自行承担风险。如果你不是作者/开发者，请不要声称对安全问题负有责任。
